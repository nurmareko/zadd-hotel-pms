# ZADD Hotel PMS Layout Patterns

## Dashboard Structure

Every dashboard follows:

1. Summary
2. Priorities
3. Operational Content
4. Historical Data

Never reverse this order.

---

## KPI Area

Position:

Top of page

Purpose:

Provide instant understanding.

A user should understand the current situation in under 3 seconds.

Examples:

- Occupancy
- Arrivals
- Departures
- Assigned Rooms

---

## Content Hierarchy

Priority 1

Current Tasks

---

Priority 2

Current Status

---

Priority 3

Supporting Information

---

Priority 4

History

---

## Card Pattern

Every card contains:

Header

Content

Optional Actions

---

Example

Room 307

VD

Guest arriving 14:00

---

## Mobile First Pattern

Users are moving.

Users are standing.

Users are working.

Design for quick interactions.

---

Primary Actions

Must remain visible.

Never hide critical actions behind menus.

---

## Housekeeping Layout

Priority Order

1. Room Number

2. Status

3. Action Button

4. Guest Context

5. Notes

6. History

Housekeepers care about:

"What should I do next?"

Design accordingly.

---

## Front Office Layout

Priority Order

1. Arrivals

2. Departures

3. Availability

4. Guests

5. Billing

6. Reports

Front Office staff care about:

"Who is arriving and leaving?"

Design accordingly.

---

## Detail Page Pattern

Header

Primary Action

Status

Information Blocks

History

Never place history above actions.

---

## Empty States

Every empty state should guide users.

Never leave blank screens.

Bad:

No data.

Good:

No rooms assigned today.

Enjoy your shift.

---

## Responsive Behavior

Desktop

Multi-column

Tablet

Two-column

Mobile

Single-column

Content should stack naturally.

No horizontal scrolling.
